# Task Service — Периодические задачи

## Что добавлено
Реализована поддержка периодических задач. Пользователь может задать правило повторения, и система будет автоматически создавать экземпляры задачи в нужные даты.

### Поддерживаемые типы:
```json
{"type": "daily", "interval": 2}           // каждые 2 дня
{"type": "monthly", "day_of_month": 15}    // 15-го числа каждого месяца
{"type": "specific_dates", "dates": ["2026-04-20"]} // конкретные даты
{"type": "parity", "parity": "even"}       // по чётным/нечётным дням
```

## Как работает
1. Создаёшь задачу с полем `recurrence` → она становится "шаблоном"
2. Фоновый планировщик (раз в час) проверяет шаблоны
3. Если сегодня подходит по правилу — создаётся копия задачи с `scheduled_date`
4. Уникальный индекс `(source_task_id, scheduled_date)` защищает от дублей

# Swagger: http://localhost:8080/swagger/
```

# Тестирование фичи
```bash
# 1. Создать задачу с повторением
curl -X POST http://localhost:8080/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Test","recurrence":{"type":"daily","interval":1}}'

# 2. Посмотреть логи планировщика
docker compose logs app -f | grep scheduler

# 3. Проверить созданные экземпляры в БД
# (подключиться к postgres и сделать SELECT)
```

> 💡 Для быстрых тестов можно временно уменьшить интервал планировщика в `main.go` с `1*time.Hour` на `10*time.Second`.

## Архитектурные заметки
- **JSONB для recurrence**: разные типы правил имеют разную структуру — удобно хранить в JSON, валидация в коде
- **Планировщик в горутине**: не блокирует API, корректно завершается через context
- **Уникальный индекс в БД**: простая и надёжная защита от дублей при масштабировании

## Предположения (где требования были неясны)
- Экземпляры задач не наследуют `recurrence` (чтобы не плодить бесконечную вложенность)
- Для `monthly` используются дни 1–30 (31-е число не поддерживается для простоты)
- Все даты в UTC
- Планировщик работает в одном инстансе; при масштабировании защита от дублей — на уровне БД
